1. 특징공학을 사용하는 이유
    
    머신러닝 알고리즘 특징 벡터이만 적용할 수 있음
    

### 2. 사용하는 방법

1. 텍스트에 대한 특징 공학
    
    **원-핫 인코딩**- 범주형 속성을 여러 이진 속성으로 변환
    
    **단어 가방(bag-of-words)** - 원-핫 인코딩 기법을 일반화해서 텍스토 데이터에 적용한 것. 전체 텍스트 문서를 이진벡터로 나타냄
    
    변형된 형태로 토큰 수, 토큰 빈도, TF-IDF 가 있음
    
    bag-of-n-grams - 말뭉치에서 가져온 n개의 단어의 시퀀스
    
2. 특징 벡터는 특정 규칙을 따르는 경우만 작동
    1. 특징 벡터의 j위치에 있는 특징이 데이터 세트의 모든 견본에서 동일한 속성을 나타내야 함
    2. 유사한 특징 벡터가 데이터 세트에서 유사한 개체를 나타내야 함
3. 범주형 특징을 숫자로 변환
    
    **빈 카운팅(bin counting)** - 그 범주가 전체에서 몇 번 나타났는지 또는 등장 비율로 치환
    
    **평균 인코딩(mean encoding)** - 범주마다 타깃 y의 평균으로 치환
    
    이진 분류에서는 **승산비(odds ratio), 로그승산비(log-odds ratio)** 도 사용할 수 있음
    
    범주형 특징에 **주기성이** 있는 경우 정수 인코딩이 제대로 안됨 → **사인-코사인 변환**
    
4. **특징 해성(feature hashing, hashing trick)**
    
    텍스트 데이터나 **값이 많은 범주형 속성**을 임의 차원의 특징 벡터로 변환.
    
    서로 다른 특징이 충돌될 수 있음
    
5. 주제 모델링
    
    **문서 속에서 숨겨진 주제(토픽)**를 자동으로 찾아 문서마다 주제 혼합 비율을 붙이는 비지도/약지도 기법
    
    **LSA** - 단어-문서 행렬 (TF-IDF)을 SVD(특잇값 분해)로 축소해 의미 차원을 얻는 선형대수 접근
    
    **LDA** - 문서는 여러 주제의 혼합물, 각 주제는 단어들의 확률 분포라는 생성확률 모델
    
6. 시계열 특징
    
    순서가 지정된 관측 **시퀀스**. 각 관측값은 **타임스탬프**, 날짜, 월.연도, 연도 등 시간관련 속성과 함께 표시
    
    **기존 시계열 데이터(classical time-series data)** - 시간에 따라 **균등한 간격**으로 관측
    
    **점 프로세스(point process), 이벤트 스트림(event stream)** - 관측치가 **불규칙**함
    
    **이벤트 스크림** → **집계연산자(count, average)**를 사용해 → 기존 시계열 데이터 변환 
    
    다음에 관찰할 수 있는 무언가 예측/ 해당 시퀀스를 생성한 현상에 대해 예측

### 4. 좋은 특징의 특성

1. 높은 예측력
    
    해당 문제와 관련된 특징의 특징
    
2. 빠른 계산 능력
3. 신뢰성
    
    항상 사용 가능해야 함
    
4. 비상관성
    
    상관관계(correlation) - 해당 값이 서로 관련되어 있음을 뜻함. 하나의 특징이 커지면 다른 특징도 커지고 반대의 경우도 성립한다면 두 특징은 상관관계가 있다고 함
    
    많은 특징이 서로 상관관계가 높으면 입력 데이터 특성이 조금만 변해도 모델 동작이 크게 바뀔 수 있음
    
    이러한 특징의 유지보수 비용이 많이 듦
    
5. 기타
    
    훈련 세트의 특징 분포가 운영 환경에서의 입력의 특징 분포와 유사
    
    특징은 단일하고 이해하기 쉽고 유지보수가 쉽도록 설계해야함
    
    단일 → 이해하기 쉽고 설명하기 쉬운 어떤 수량
    

### 5. 특징 선택

문제에 따라서 모든 특징이 똑같이 중요하지 않음

일부 특징이 몇가지 훈련 견본에만 0이 아닌 값을 갖게되면 유용한 패턴 학습이 어려울 수 있음

특징 벡터 차원이 너무 높은 경우 훈련시간이 오래걸림. 램 용량 부족

→ **중요한 특징만 유지** → 시간 절약, 모델 품질 개선

1. **긴 꼬리 자르기**
    
    일부 견본에만 해당하는 정보를 나타내는 특징은 제거할 수 있음
    
    하지만 그게 중요한 정보일 수 있음
    
2. **보루타(Boruta)**
    
    랜텀 포레스트 모델을 반복적으로 훈련하고 통계 테스트를 통해 중요한 특징과 중요하지 않은 특징을 구분
    
    **랜덤 포레스트**는 훈련 세트에서 훈련에 사용할 견본과 사용하지 않은 견본을 분리하여 트리를 테스트 하는것을 반복. 이 과정에서 특징 중요도 점수를 구할 수 있음 → 그러나 이 점수만으로 특징과 목표 간의 의미있는 상관관계를 반영하지 못하는 경우가 많음 → 보루타 등장
    
    랜덤으로 뽑은 원본 특징의 복사본을 추가하여 특징 목록 확장하고 분류기 만듦 → 원본 특징의 중요성을 평가하기 위해 랜덤하게 뽑은 특징과 비교 → 랜덤보다 중요도가 높고 통계적으로 유의미한 것만 중요한 특징으로 간주
    
    **한줄 정리: 각 특징 열을 랜덤 셔플해서 만든 섀도(shadow)특징을 원본 특징과 함께 모델에 넣고 원본이 섀도보다 유의미하게 큰지 비교**
    
3. **L1-정규화**
    
    **정규화**: 모델의 일반화(generalization)을 개선하는 다양한 기술을 포괄하는 용어
    
    **일반화**: 훈련 단계에서 사용하지 않은 견본의 레이블을 모델이 얼마나 올바르게 예측하는지
    
    **L1** - 너무 복잡한 모델에 패널티를 줌. 
    
    일부 매개변수가 0인 **희소모델을** 생성
    
4. 과제별 특징 선택
    
    ex) 자연어 처리: 불용어 제거 등
    

### 6. 특징 합성

1. 특징 이산화
    
    연속형 변수를 구간으로 잘라 **범주형** 변수로 바꾸는 것
    
    - **균일 너비** 비닝
    - **k-평균 기반** 비닝
    - **분위서(quantile)기반** 비닝
2. 관계형 데이터베이스에서 특징 학습
    
    표본 평균과 표본 표준편차의 값을 특징으로 사용
    
3. 데이터로부터 특징 합성
    
    군집화 사용
    
    훈련 데이터의 특징 벡터에 k-평균  군집화 적용 → 특징 벡터에 k개의 추가 특징 ㅌ추가
    
4. 다른 특징으로부터 특징 합성
    
    신경망은 단순한 특징을 독특한 방식으로 결합해 복잡한 특징을 학습하는 능력이 있음
    

**특징 교차(feature-crossing)**:+,-,*,/ 같은 간단한 산술 연산자를 적용해서 새 특징 생성

### 9. 특징 스케일링

모든 특징을 **동일하거나 매우 유사한 범위의 값이나 분포**로 만드는 것

어떤 개별적인 특징이 **지배적인 영향을 끼치지 않도록** 해줌

매우 큰 숫자를 계산할때 발생하는 **오버플로 위험 줄여줌**

1. **정규화**
    
    수치형 특징의 값을 [-1,1] 또는 [0,1] 범위로 변환
    
    단점: 정상 범위에 이쓴ㄴ 특징값을 매우 작은 범위로 압축하게 될 수 있음 → 클리핑 - 극단적인 값 대신에 합리적인 값 선택
    
2. **표준화/ z-점수 정규화**
    
    평균 0, 표준편차 1인 표준정규분포의 속성을 갖도록 재조정
    

정규화는 균일 분포를 따르는 데이터에 잘 작동하고 표준화는 정규 분포를 따르는 데이터에 잘 작동하는 경향이 있음

### 10. 특징 공학에서 데이터 누출

1. 잠재적인 문제
    
    전체 데이터 세트를 사용해 각 빈의 범위나 특징 스케일링 인수를 계산한 다음에 데이터를 훈련, 테스트로 분할한다면. 훈련 데이터의 일부 특징값은 테스트 셋에 속하는 견본을 사용하여 얻은 결과가 됨
    
    단어 가방 모델 - 어휘를 만들고 분할 시
    
2. 솔루션: 먼저 분할하고 훈련 셋에 특징공학을 사용

### 11. 특징 저장과 문서화

1. 스키마 파일: 특징을 설명하는 문서
2. 특징 저장소 - 특징을 저장, 문서화, 재사용, 공유할 수 있는 곳
    
    직면하는 문제들
    
    - 특징을 재사용하지 않음 - 서로 다른 엔지니어와 팀에서 개체의 동일한 속성을 나타내는 특징을 여러 차례 중복 구현
    - 특징의 정의가 다양함 - 팀마다 특징을 다르게 정의해서 특징 설명서를 항상 참고할 수 없음
    - 계산 집약적인 특징 - 일부 머신러닝 모델은 유용한 정보를 제공하는 특징이 아니라 계산이 효율적인 특징을 사용. 이런 특징을 빠른 저장소에 저장하면 실시간으로 사용할 수 있음
    - 훈련과 서빙 간의 불일치 - 일반적으로 모델은 과거 데이터로 훈련하지만 서빙할 때는 실시간으로 온라인 데이터를 입력받음 → 오프라인과 온라인 모드에서 동일한 입력 데이터 개체에 대해서 각 특징값이 동일해아 함
    - 특징의 만료 시점을 알 수 없음 - 새로운 입력 견본이 운영 환경에 도입되면 어떤 특징을 다시 계산해야하는지를 정확히 알 수 없음

### 12. 특징 공학 모범 사례

1. 여러 가지 간단한 특징 생성
2. 기존 시스템 재사용
3. 필요한 경우에만 식별자를 특징으로 사용
    
    일반적인 경우에는 특정한 동작을 하고 다른 경우에는 또 다른 동작을 하는 모델을 만들 수 있음
    
4. 가능하면 크기를 줄인다
    
    특징 해싱, 유사한 값 그룹화, 긴 꼬리 그룹화, 특징 제거
    
5. 계수 사용은 신중하게
6. 특징은 필요할 떄 선택
7. 코드 테스트는 주의 깊게
    
    특징 공학 코드는 신중하게 테스트 해야함. 단위 테스트로 각 특징 추출기를 테스트 해야함
    
8. 코드, 모델, 데이터의 동기화 상태 유지
9. 특징 추출 코드 분리
10. 모델과 특징 추출기를 함께 직렬화
11. 특징값 기록
