### 1. 심층 모델 훈련 전략

훈련을 시작할 때 제일 먼저 하는 일

네트워크 토폴로지 (아키텍처 구조) 들의 후보 리스트를 만드는 것

무슨 말이냐 ?

1. 문제 정의:
    
    이미지 분류냐, 시계열 예측이냐 등등
    
2. 후보 아키텍처(토폴로지) 목록 만들기
    
    ex) 이미지 분류 - 5층짜리 CNN, ResNet, MobileNet, 깊은 커스텀 CNN 등 후보 리스트 작성
    
3. 학습 후 적절한 토폴로지 선택 → 튜닝

왜? 이게 먼저냐?

- 토폴로지가 성능의 상한성을 정해줌(아무리 튜닝 잘해도 구조 자체가 안맞으면 성능이 별로임 ex. 긴 시퀀스인데 얕은 MLP를 쓰면 한계가 있음)
- 자원/환경의 제한도 고려

생으로 모델을 훈련할 수 있지만 사전학습 모델로 시작할 수 있음

장점: 사용자가 갖지 못하는 엄청난 양의 데이터로 훈련이 됨

사전학습 모델의 활용

1. 학습된 매개변수를 사용하여 사용자의 모델을 초기화
2. 새로운 모델의 특징 추출기로 사용

**1. 신경망 훈련 전략**

기존 모델을 사용해 새 모델을 만드는 것을 전이 학습(transfer learning)

1. 성능 지표 정의
2. 비용 함수 정의
3. 매개변수 초기화 전략 선택
4. 비용함수 최적화 알고리즘 선택
5. 초매개변수 조정 전략 선택
    1. 수동 - 경험, 감으로
    2. 그리드 서치 - 값을 설정해 놓고 가능한 모든 조합으로 실험
    3. 랜덤 서치 - 값의 범위를 설정하고 그 범위 내에서 랜덤으로 파라미터값 설정해 실험
    4. 베이즈 최적화 - 하이퍼파라미터 → 성능” 함수를 확률 모델로 근사해 놓고,
    그 모델을 보고 다음에 어디를 실험할지 똑똑하게 고르는 전략
    5. 진화/유전 알고리즘 - 여러 하이퍼 파라미터 조합으로 잘하는 애들을 선택,변화시켜 더 좋은 조합으로 만들기
6. 조정 전략을 사용해 초매개변수값의 조합 선택
7. 비용함수를 최적화하도록 최적의 하이퍼파라미터로 알고리즘 모델 훈련
8. 테스트 하지 않은 매개변수가 있으면 다른 하이퍼파라미터 조합 선택
1. **성능 지표 및 비용함수**
    
    모델을 훈련하기 위해 학습 알고리즘이 최적화 할 대상이 되는 비용함수를 정의
    
    MSE, 크로스 엔트로피(정답 클래스에 할당한 확률이 얼마나 낮은지를 측정)
    
    크로스 엔트로피 예시
    
    - 정답: 클래스 2
        
        → one-hot 정답: y=[0,0,1]y = [0, 0, 1]y=[0,0,1]
        
    - 모델 예측 확률 - p=[0.1, 0.2, 0.7]
    - 손실: L=−(0⋅log0.1+0⋅log0.2+1⋅log0.7)=−log0.7
    - 오답일땐: L=−log0.1≈2.302
2. **매개변수 초기화 전략**
    1. 모두 0 또는 1으로 초기화 → 시작점이 같아서 같은 방향으로만 학습
    2. 작은 랜덤값 → 층이 깊으면 그래디언트 소실/폭발
    3. 입력/출력 차원을 고려한 전략들(Xavier, He)
3. **최적화 알고리즘**
    
    미분 가능한 함수의 지역 최솟갑을 앚기위한 반복적인 최적화 알고리즘
    
    1. 경사 기반 - 손실함수를 미분해 그래디언트를 구하고 그 방향으로 파라미터를 움직임
        1. Gradient Decent, SGD + Momentum, Adagrad, RMSProp, Adam등
    
    경사하강법: 정의역의 임의의 지점에서 시작 → 현재 지점에서 기울기에 비례해 이동
    
    학습률: 업데이트 강도(매우 민감). 너무 크면 수렴이 안되고, 나무 작으면 학습 속도가 느려짐
    
    미니배치 경사하강법: 훈련 데이터의 작은 부분집합을 사용해 기울기 계산 → 속도 빠름
    
4. 학습률 감소 스케줄
    
    학습이 진행됨에 따라 학습률을 점진적으로 줄이는 것.
    
    1. 시간 기반 학습률 감소 스케줄: 이전 에포크의 학습률에 따라 학습률 변경. 시간에 따른 변화(공식에 시간이 있음)
    2. 단계 기반 학습률 감소 스케줄:  사전 정의된 일부 드롭 단계에 따라 학습률 변경 (정해진 비율만큼 딱딱 줄어듬)
    3. 지수 학습률 감소 스케줄: 매 step/epoch마다 고정 비율(γ)을 곱하는 형태
5. 정규화
    1. 드롭아웃: 학습 할때마다 랜덤으로 일부 노드를 계산에서 제외
    2. 조기중지
    3. 배치 정규화 - 미니배치 단위로 각 레이어의 출력을 정규화해서 학습을 안정, 빠르게 만듬
        - 각 레이어의 입력 분포가 크게 변하지 않아 그래디언트 폭주/소실이 줄어듦
        - 정규화 효과 있음
6. 네트워크 크기 검색 및 초매개변수 조정
    
    적당한 모델 시작 → 훈련 데이터로 훈련이 잘 될 때까지 모델 크기를 키움 → 검증셋으로 평가
    
    하이퍼 파라미터별 민감도
    
    - 학습률 -높음
    - 학습률 스케줄 - 높음
    - 손실함수 - 높음
    - 계층단 단위 수 - 높음
    - 매개변수 초기화 전략 -중간
    - 계층 수 - 중간
7. 다중 입력 처리
    
    다중 모드 데이터로 작업할 수 있도록 얕은 알고리즘 조정은 어려움 → 신경망을 사용하면 CNN은 이미지 임베딩, RNN은 텍스트 임베딩. 연결 후 분류
    
8. 다중 출력 처리
    
    멀티 레이블 문제로 변환 가능
    
    출력이 다중 모드일 경우(객체의 좌표와 객체를 설명하는 것)
    
    이미지를 읽고 임베딩 변환 → 하나는 좌표 예측 → 다른 하나는 태그 예측
    
9. 전이 학습
    
    사전 학습된 모델을 이용해 새로운 모델 구축
    
    1. 사전 학습 모델을 초기 값으로 사용
    2. 사전 학습된 모델을 특징 추출기로 사용 
        
        출력층에 새 층을 추가해서 새 데이터로 학습해 업데이트.
        

### 2. 모델 쌓기

앙상블 학습: 성능이 떨어지는 여러 기본모델의 조합으로 앙상블 모델을 훈련하는 것

1. **학습 유형**
    
    랜덤 포레스트, 그래디언트 부스팅 - 약한 모델 여러개 합쳐 강력한 모델을 얻음
    
    여러 모델을 결합했을 때 더 나은 성능을 얻을 수 있는 이유: 상관관계가 없는 여러 모델이 결과가 동일하다면 그것은 올바른 결과일 가능성이 더 높기 때문.
    
    평균화: 모든 기본 모델의 예측의 평균을 구함
    
    다수결: 분류 작업일때 더 많은 예측을 한 클래스를 반환
    
    모델 쌓기(stacking): 여러 개의 기본 모델(base models)의 예측 결과를 모아서, 그 예측들을 입력으로 받는 **메타 모델(meta-model)**을 한 번 더 학습시키는 앙상블 방법
    
    배깅(bagging) - 같은 종류 모델을 데이터 샘플을 여러번 리샘플(부트스트랩) 해서 학습
    
    부스팅(boosting) - 약한 모델을 순서대로 쌓아 올리면서 앞 모델이 틀린부분을 뒷 모델이 좀 더 집중
    

### 3. 분포 이동 처리

홀드 아웃 데이터는 실제 운영 환경에서의 데이터와 유사해야 함

ex) 인스타 사진 분류 훈련 목적. 레이블링 웹 크롤링한 이미지는 많은데 라벨링된 인스타 사진은 별로 없을 땐, 웹 크롤링 데이터를 사용해 모델을 훈련한 다음 이 모델로 인스타 사진 분류 가능

분포 이동: 훈련 데이터와 테스트 데이터의 분포가 동일하지 않을 때

1. **분포 이동 유형**
    - 공변량 이동 - 특징값의 이동 (특징값 분포가 바뀜)
        - 학습할 때 본 입력 특징들의 분포랑, 실제 사용할 때 입력 특징들의 분포가 달라졌는데, 특징과 레이블 사이의 관계 자체는 그대로인 상황
        - ex) 학습에는 낮, 도심위주 학습 → 실제: 밤, 시골길도 많음
    - 사전 확률 이동 - 목푯값의 이동 (레이블 분포가 바뀜)
        - 레이블의 비율이 바꼈는데 레이블이 정해졌을 때 특징분포는 그대로인 상황
        - ex) 스팸 분류기 - 학습떈 반반인데 실제 환경에는 스팸 비율이 5%정도
    - 개념 이동 - 특징과 레이블 간의 관계 변화
        - 같은 x가 들어와도 y가 달라지는 상황
        - 이전: 특정 온도는 ok 그러나 안전 기준 강화돼서 위험한 기준 변경
    
    훈련 세트의 크기에 비해서 테스트 세트의 수가 상대적으로 많다면 테스트 셋의 일부를 훈련세트로 일부는 검증세트로 사용할 수 있음. 
    
    그러나 일반적으론 훈련 세트가 매우 많음. → 적대적 검증을 사용
    
2. **적대적 검증** 
    
    훈련 데이터와 테스트 데이터가 얼마나 다른지 확인하기 위해 둘을 구분하는 분류기를 만들어 보는 방법
    
    이 분류기가 잘 못맞춘다(정확도 0.5) → 분포 비슷(아주 좋음)
    
    목적:
    
    분포가 다르다는 사실 인지
    
    문제가 되는 특징 찾기 → 그런 특징을 제거하거나 변형, 등 수정해서 분포 차이 줄임
    
    분류기가 test라고 예측한 것을 검증셋으로 사용
    
    반대로 확실하게 train이라고 예측한것은 훈련 셋에서 제외
    

### 4. 불균형 데이터 세트 처리

기존 오버샘플링, 언더샘플링 등 데이터 준비과정에서 하는 과정이 있고

이번장에는 학습 중에 적용하는 기술들

1. 클래스 가중치
    
    소수 클래스에 큰 가중치를 할당. → 소수 클래스 샘플을 무시하기 어려워 짐. 
    
    소수 클래스에 대한 오분류 손실을 높게 설정 → 이런 샘플의 오분류를 피하려고 함 → 다수 클래스 샘플에 대한 오류 비용 발생 가능성 있음
    
2. 다시 샘플링한 데이터 세트 앙상블
    
    다수 클래스를 n개로 나누고. 소수와 작은 부분집합을 결합해 데이터 세트를 결성.
    
3. 기타
    
    확률적 경사 하강법 - 클래스 별로 다른 학습률(다수-낮은, 소수- 높은). 소수 클래스에 대해 계산할 때마다 모델 매개변수를 여러번 업데이트
    

### 5. 모델 업데이트

때로는 모델이 예측한 클래스뿐만 아니라 예측한 클래스가 얼마나 정확한지 나타내는 확률을 함께 반환하는 것도 중요

1. **잘 교정된 모델**
    
    x가 클래스 y에 속할 확률로 해석할 수 있는 점수를 함께 반환할 때 모델이 잘 교정되었다 라고 함 (모델이 내놓는 ‘확률 예측’이 실제 발생 빈도와 잘 맞는 모델)
    
    정확도랑 무슨차이일까? ex)0.8로 예측한 데이터를 모으면 진짜 양성 클래스의 비율이 0.8정도 되어야 함.
    
    →이 확률을 믿고 의사결정해도 되는가? 를 보는 품질느낌
    
2. **교정 기술**
    - 플랫 스케일링(이진분류)
        
        원래 모델 점수가 실제 클래스의 비율과 일치하지 않다면 검증 데이터셋으로 1차함수+sigmoid로 모델이 말하는 확률을 현실적인 확률로 다시 바꿔주는 방법
        
    - 아이소토닉 회귀(Isotonic)
        
        플랫 스케일링은 직선+시그모이드라서 복잡한 관계는 따라가지 못함
        
        입력이 증가하면 출력도 증가한다는 것을 가정(모델 점수가 높을 수록 실제 비율도 높아야 함)
        
        → 점수 높은애가 낮은애보다 실제 비율이 작지 않게 앞뒤 값의 평균으로 보정
        

### 6. 문제 해결 및 오류 분석

모델의 성능 저하가 코드 버그, 훈련 데이터, 학습 알고리즘, 파이프라인 설계방식에 문제가 있어서인지 등등 판별하기 어려움

1. **모델이 성능이 떨어지는 이유**
    1. 과소적합
        - 모델 아키텍처나 학습 알고리즘의 표현력이 충분하지 않음
        - 정규화를 너무 많이 함
        - 최적이 아닌 하이퍼파라미터 선택
        - 설계한 특징의 예측력이 충분하지 않음
        - 모델을 일반화하는 데 필요한 데이터가 충분하지 않음
        - 코드에 버그가 있다
    2. 과적합
        - 일반화를 위한 데이터가 충분하지 않다
        - 모델이 충분히 정규화 되지 않았다
        - 훈련 데이터와 홀드아웃 데이터의 분포가 다르다
        - 최적이 아닌 하이퍼 파라미터
        - 특징의 예측력이 낮다

2. **반복적 모델 개선**

레이블링된 새로운 데이터를 사용할 수 있는 경우 간단한 과정으로 모델 개선할 수 있다

- 지금까지 확인된 하이퍼파라미터의 최적값을 사용해 모델 훈련
- 검증 세트의 작은 부분집합을 통해 모델 테스트
- 위에서 사용한 작은 검증셋에서 가장 빈번한 오류패턴을 찾아본다. 나중에 이 샘플을 검증셋에서 제외
- 새 특징 생성, 더 많은 훈련 데이터 추가해 오류 패턴 수정

오류 분석의 단순화된 버전

1. **오류 분석**
    
    발생 가능한 오류
    
    - 균일하고 모든 사용 사례에서 동일한 비율로 나타남
    - 집중적이고 특정한 유형의 사용사례에서 더 자주 나타남
    
    집중된 오류: 특정한 패턴을 보임. 학습 데이터가 반영하진 못한 사례에서 주로 발생
    
    균일 매니폴드 근사 투영(UMAP)이나 오토인코드 같은 차원축소 기법으로 에러가 생기는 영역을 보는 방법
    
    정답을 맞춘 샘플과 틀린 샘플을 눈으로 확인해서 분석할 수 있다
    
    - 붉은 점(오류)이 특정 영역에 몰려 있다 →
        
        → 그 영역의 데이터 타입/특징을 분석
        
    - train은 이쪽, test는 저쪽 구름에 몰려 있다 →
        
        → **공변량 이동(covariate shift)** 의심
        
    
    오류 패턴을 수정하기 위해
    
    입력 전처리, 데이터 증강, 더 많은 훈련 셋 확보, 새 특징 설계를 조합해 사용할 수 있음.
    
2. **복잡한 시스템의 오류 분석**
    
    ex) 입력 → **언어감지 → 번역 → 분류** → 결과
    
    목표 73%성능.  각 모델 성능 95%, 90%, 85% → 곱하면 73%
    
    얼핏 보기엔 분류기의 정확도를 높이면 전체 성능을 올릴 수 있을 것처럼 보이지만 그렇지 않을 수도 있음.
    
    ex) 언어 감지 예측기가 스페인어와 포루투갈어를 혼동해도 기계 번역 모델은 적절한 번역을 생성할 수 있음.
    
    분류기 성능 개선의 여지가 별로 없을 땐? 언어 탐지, 번역모델의 성능을 개선해야 할것.
    
    **부분별 오류 분석(error analysis by parts)**:전체 시스템의 잠재적 상한선을 결정하는 한가지 방법.
    
    한 모델의 예측을 인간이 제공한 완벽한 레이블로 대체한 다음 성능 측정해서 무엇을 개선시킬지 결정하면 됨
    
3. 부분지표 사용
    
    검증 데이터를 여러 부분집합으로 분할해서 각 부분집합에 모델을 적용해 성능 지표 개산
    
4. 잘못된 레이블 수정
    
    레이블링이 잘못된 샘플을 찾는 방법: 모델이 훈련 데이터에 인간이 할당한 레이블과 다른 예측을 한 견본을 분석해보고 모델이 진짜 맞다면 바꿈
    
    예측 점수가 임계값에 가까운 예측도 잘못될 가능성 있음
    
    여러 레이블러에게 레이블링
    
5. 추가로 레이블링할 견본 찾기
    
    오류 분석을 통해 어느 특정 영역에 대해 더 많은 레이블링된 데이터가 필요한지 알 수 있다.
    
    가장 성능이 좋은 모델을 사용해 레이블링 하고 예측 점수가 임계값에 가까우면 직접 레이블링
    
6. 딥러닝 문제 해결
    
    작업 순서
    
    1. 작은 모델로 시작.
    2. 훈련 데이터 셋을 하나의 미니 배치 크기로 줄인 후 훈련
    3. 과적합되는지 확인
        1. 발생하지 않으면 → 코드나 데이터에 문제가 있음(훈련 데이터가 작으면 기본적으로 외우는데 모델이 이것도 수행하지 못함)
        
        가능한 징후와 원인들
        
        - 오류가 커짐: 손실함수 기울기 부호 바뀜, 학습률 너무 높음, 잘못된 차원에 대한 소프트맥스 계산
        - 오류 폭발: 수치적 문제, 학습률 너무 큼
        - 오류 진동: 데이터, 레이블이 손상됨, 학습률이 높음
        - 오류 정체: 학습률이 낮음, 모델 전체로 기울기 전달되지 않음, 정규화 너무 많음, 손실 함수에 입력이 잘못됨, 데이터 또는 라벨 손상
        
        b. 과적합되면 다음단계
        
    4. 전체 데이터셋에 훈련하고 하이퍼파리미터 조정
    5. 전체 성능이 불만족하다면, 모델 복잡성 증가 또는 데이터(전처리 변경, 특징추가) 업데이트
    
    작은 훈련셋 대신 간단한 합성 훈련 세트 생성, 클래스 개수나 이미지 해상도, 등을 줄임
    

### 7. 모범 사례

1. 좋은 모델 제공
    
    좋은 모델?
    
    - 성능 지표 측면에서 만족할 만한 품질
    - 운영 환경에서 안전하게 서비스 제공
        - 로딩 중이거나 로드된 후에 오류나 예기치 않은 입력이 있을 경우 서빙 시스템이 충돌하거나 오류 일으키지 않음
        - 자원을 과도하게 사용하지 않음
2. 검증된 오픈소스 활용
    
    수학 - Numpy 
    
    신경망 연산, 미분, 최적화 → Pythrch, TensorFlow 등등을 검증된 라이브러리 사용
    
3. 비즈니스별 성능 측정 최적화
    
    검증 오류율이 증가하더라도 비즈니스에 특화된 지표를 최적화하는 하이퍼파라미터 조정에 더 집중
    
4. 밑바닥부터 개선
    
    데이터가 업데이트 되면 하이퍼파라미터를 다시 조정해야 함
    
    신경망같은 모델을 반복적으로 개선할 수 있지만, 웜 스타트(이전에 학습한 모델을 가져와서 같은데이터에 또 학습시키는 것) 방식은 피함 → 새 훈련데이터만 추가적으로 반복 훈련해 모델 개선
    
    파괴적 망각: 기존 잘 작동 모델이 새로운 것을 배우면서 그 능력을 잊는 상황
    
5. 연속적인 정정 방지
    
    correction cascade
    
    특정 문제 A에 대한 모델 m이 있는데 살짝 다른 문제 A’이 생기면 m위에 조금씩 수정해서 m’, m’’을 만드는 식으로 계속 덕지덕지 보정층을 쌓아 올리는 것
    
    → 모델을 제대로 다시 고치는 대신, 출력 결과 위에 온갖 예외 처리·핫픽스·규칙을 계속 덧붙이는 패턴
    
    왜 안좋나?
    모델 개선이 점점 불가능해짐
    구조가 점점 지저분·취약해짐
    
6. 연속된 모델을 주의해서 사용
    
    model cascading
    
    여러 모델을 연결해서 앞 모델의 출력이 뒷 모델이 입력이 되는 구조
    
    오류/편향이 “전 단계에서 다음 단계로” 그대로 전파·증폭됨
    단계 간 강한 결합(coupling) 때문에 유지보수가 폭탄이 됨
    
7. 효율적인 코드 작성, 컴파일, 병렬화
    
    라이브러리를 활용해 빠른 계산
    
    병렬화
    
    속도가 빠른 디스크에 데이터를 저장, 분산 컴퓨팅
    
    접착코드(glue code)를 최소화
    
    서로 다른 라이브러리, 서비스, 스크립트, 포맷 등을 억지로 맞춰 주기 위한 “중간 어댑터 코드
    
    여기저기 많이 쌓이면 시스템이 복잡해지고 유지보수/디버깅 비용이 크게 올라감
    
8. 최신 데이터와 이전 데이터에 대한 테스트
    
    모델이 최근 수집된 데이터에 대해 어떻게 작동하는지 관찰. 성능이 악화되면 데이터 누출, 분포이동이 가장 가능성 높은 원인.
    
9. 똑똑한 알고리즘 보다 더 많은 데이터
10. 새로운 데이터가 좀 더 좋은 특징보다 뛰어남
11. 작은 진전의 수용
    
    혁진적인 아이디어를 찾는 것보다 모델에 대한 작은 개선이 많이 쌓이면 원하는 결과를 더 빨리 얻을 수 있음
    
12. 용이한 재현성
    
    대부분의 머신러닝 알고리즘은 확률적임. → 재현성을 높이기 위해 랜덤시드 설정
    
    재현성을 위해 모델과 관련된 모든 정보를 같이 제공해야 함
    
    - 고려된 범위와 사용된 기본값을 포함한 모든 초매개변수의 사양
    - 최적의 초 매개변수 구성을 선택하는 데 사용한 방법
    - 후보 모델을 평가하는 데 사용한 특정한 턱도나 통계의 정의 및 최상의 모델에 대한 값
    - 사용된 컴퓨팅 인프라에 대한 설명
    - 훈련된 모델의 평균 실행 시간 및 예상 훈련 비용
