### 1. 데이터에 대한 질문

데이터 수집을 시작하기 전에

1. 데이터를 구할 수 있는가?
    
    구할 수 있을 경우 법적 규범에 의해 보호하고 잇는지?
    
    민감한 내용을 담고 있고 향후에 사용하고 있는지 등등을 해결한 후 사용 가능
    
2. 데이터 세트의 크기가 충분히 큰가?
    
    충분한 데이터를 즉시 사용할 수 있을지 확실하지 않은 경우 새로운 데이터가 생성되는 빈도를 확인.
    
    학습 곡선을 그려보고 충분한 데이터를 수집했는지 확인하는 방법 (어느 수준부터는 성능향상이 정체됨 → 추가 데이터로 부터 얻는 이득 감소)
    
    학습 알고리즘이 성능이 정체되면, 이는 더 많은 데이터가 더 나은 모델을 훈련하는 데 도움이 되지 않는다는 신호일 가능성 2가지
    
    1. 특징이 목표를 구분하기에 담고 있는 정보가 부족하면 데이터가 많아져도 얻는 이득이 적음.
        1. N을 늘리면 분산은 줄지만 정보가 적으면 편향이 지배. → 데이터만으로는 bias를 못 줄임
        2. 문제를 푸는데 조건이 적으면 우연한 패턴에 의존 → 더 많은 표본은 같은 한계를 반복해서 관측
    2. 보유한 데이터로는 원하는 복잡도의 모델을 추우분히 훈련하기 어려운 학습 알고리즘을 사용했다
        1. 같은 분포의 비슷한 표본만 늘림
    
    → 데이터 규모를 ‘질적’으로 크게 바꾸거나, 알고리즘/모델을 데이터 친화적으로 바꾸는 방향으로 해결
    
3. 데이터를 사용할 수 있나?
    
    데이터에 통계적 분류기가 모델의 성능을 좌우
    
    스프레드시트 형식일 때 깔끔한지
    
    깔끔한 데이터 - 데이터셋을 구조에 맞게 구성했는지
    
    결측값 대체, 중복 제거
    
    데이터가 만료됐거나 최신 상태가 아닌지
    
    불완전한 데이터이거나 실제 상황을 대표하지 못하는 데이터인지
    
    ex) 얼굴표정 인식 → 백인으로만 데이터 구축 → 흑인이나 동양인은 적음
    
    ex) 뉴스 웹사이터에서 데이터 스크랩 → 다운로드 날짜가 뉴스 키사 텍스트와 동일한 문서에 저장될 가능성, 한번에 하나의 주제 스크랩 → 요일마다 다른 주제 스크랩 → 모델이 날짜-주제 상관관계를 학습 → 전처리를 해야함
    
4. 데이터를 이해할 수 있나?
    
    각 속성에 어디에서 왔는지, 정확히 무엇을 나타내는지
    
    데이터 누출(data leakage), 목표 누출(target leakage)
    
    훈련 시점에 원래는 알 수 없어야 하는 정보가 모델에 유입
    
    정답과 직접/간접적으로 동치인 정보가 특징에 들어감(ex 중개수수료 → 집값에 직접적인 정보가 들어감)
    
5. 데이터를 신뢰할 수 있나?
    
    수집 절차에서 **신뢰성**이 결정
    
    레이블을 믿을 수 있나?
    
    **여러 작업자의 과반수나 평균**으로 레이블 결정해 신뢰도 높임
    
    **지연된 특성**이나 **간접적인 특성**에도 영향을 받을 수 있음.
    
    **지연된 레이블**: 모델이 예측을 한 시점에는 정답 라벨이 없고, 꽤 시간이 지난 뒤에야 라벨이 도착하는 상황 → 현재와 미래 사이에 특징 벡터에 반영되지 않은 이벤트 발생 →신뢰성 감소
    
    **간접 레이블**: 우리가 정말로 알고 싶은 정답을 직접 모으기 어렵거나 늦게 알 수 있을 때, 그와 상관이 높은 ‘대체 신호’로 임시 라벨을 붙이는 것 → 목적에 따라 신뢰도 하락 (**지금 당장 쓸 수 있지만, 진짜 정답은 아님)**
    
    **피드백 루프(feedback loop)** - 모델이 만든 출력이 유저/운영 행동을 바꾸고 바뀐 행동이 다시 다음 학습데이터로 들어와 모델을 더 바꾸는 순환 → 데이터의 불안정성 원인
    
    **why?** 보여준 것만 라벨이 생겨 데이터 분포가 한쪽으로 쏠림. 예측이 현실을 바꿔 정답 생성 과정이 달라짐
    

### 2. 일반적인 데이터 관련 문제

1. **높은 비용**
    
    수집에도 비용이 들지만, 레이블링하는데도 비용이 발생
    
    잡음이 있는 사전 레이블링(noisy pre-labeling): 모델이 먼저 예측값으로 라벨링 함 → 이후 인간이 검수 → 맞는건 그대로 틀린건 수정
    
2. **품질 불량**
    
    원시 데이터 품질, 레이블링 품질 2가지
    
    원시데이터 문제 - 잡음, 편향, 낮은 예측력, 오래된 견본, 특잇값, 누출
    
3. **잡음(noise)**
    
    데이터에 포함된 오류/변동. 예측에 필요한 정보를 흐리게 만들어 학습/평가를 왜곡
    
    이미지가 흐려지거나 지워짐, 텍스트는 일부 단어가 연걸되거나 분할 등등
    
    노이즈가 있으면 과적합이 될 수 있음. 그러나 빅데이터에서는 입력 특징의 작은 부분에 너무 의존하는 것을 방지해 오히려 정규화 효과를 가져오게 됨.
    
4. **편향(bias)**
    
    데이터가 수집/가공/라벨링되는 과정에서 특정 값/집단/상황이 체계적으로 과소/과대표집 되거나 왜곡되어, 모델이 평균적으로 참값에서 한쪽으로 치우치게 되는 문제
    
    - **선택 편향(selection bias)** - 데이터를 모으는 방식이 특정 집단·상황을 더(혹은 덜) 포함.
        
        쉽게 구할 수 있고, 편리하고, 비용 효율적인 데이터 소스를 선택하도록 왜곡하는 경향 → **표본이 비확률적으로 선택되어 ‘대표성’이 깨지는 모든 상황**
        
        **해결** -특정 데이터 소스를 선택한 이유를 체계적으로 질문
        
        이유가 단순히 낮은 가격이라면 주의
        
    - **자기 선택 편향(self-selection bias)** - 데이터에 포함될지 ‘대상이 스스로 결정’해서 표본이 모집단을 제대로 대표하지 못하는 상황.
        
        완전히 제거 불가. 일반적으로 설문조사에서 나타남. 질문조사는 짧게
        
        응답자를 미리 선택
        
    - **생략된 변수 편향(omitted variable bias)** - 정확한 예측이 필요한 특징이 데이터에 없을 때
        
        들어가야 할 중요한 설명변수 Z 빼먹은 채, 관심 변수 X가 결과 Y에 미치는 효과를 추정하면, 그 추정치가 **체계적으로 왜곡(편향)** 되는 현상.
        
        사용할 수 있는 모든 정보를 사용. 차원이 높아지고 희소해지지만 정규화를 잘하면 어떤 특징이 중요한지 아닌지 모델이 파악 가능
        
    - **sponsorship, funding bias** - 자금을 댄 스폰서의 이해관계에 유리한 방향으로 결과가 치우치는 현상.
        
        데이터 소스 소유자가 데이터를 제공하려는 동기를 살펴보면 줄일 수 있음
        
    - **샘플링 편향 (sampling bias)** - **모집단을 대표해야 할 표본이 수집 방식 때문에 한쪽으로 치우쳐**, 통계 추정이나 모델 학습이 체계적으로 왜곡되는 것
        
        생산 단계에서 관찰되는 데이터의 속성의 실제 비율을 유지핟록 샘플링
        
    - **편견 편향(prejudice)** - 설계자의 개인적/집단적 편견이 라벨 규칙에 들어가는 경우(ex, 사투리를 더 공격적으로 류, 남성은 직장 여성은 야외에서 더 많이 관찰 → 인식 어려움)
    - **고정관념 편향(stereotype bias)** - 사회에 퍼진 고정된 연상이 데이터 분포, 표현, 모델 파라미터에 스며든 경우.  (ex. word2vec에서 프로그래머 - 남자 + 여자 → 주부로 예측, 번역기가 언어 중성 표현을 “그는 엔지니어/그녀는 간호사”로 성별화)
        
        편견/고정관념 편향은 통제 가능 → 고르게 분포된 견본에 학습 알고리즘 적용
        
    - **체계적인 값 왜곡(systematic value distortion)** - 값이 생성·측정·기록·전처리되는 과정에서, 우연(랜덤) 오차가 아니라 ‘일관된 방향’으로 치우치게 만드는 메커니즘.
        
        일반적인 잡음으로 생각하면 안됨. 일반적인 잡음은 데이터가 크면 평균회 되지만 측정값이 일방되게 한 방향으로 치우쳐 있으면 모델 품질 저하
        
        여러가지 측정 장치를 사용
        
    - **실험자 편향(experimenter bias)** -  연구자(실험자)의 기대·신념·선호가 실험의 설계·수행·측정·분석·보고 전 과정에 스며들어 결과를 한쪽으로 치우치게 만드는 현상
        
        질문한 내용을 여러사람이 검증하도록 하면 피할 수 있음.
        
        개방향 질문을 선택
        
    - **레이블링 편향(labeling bias)** - 라벨링 과정에서 일부 레이블에는 엄격할 수 있고 다른 일부는 좀 덜 엄격할 수 있어 편향
        
        여러 레이블러에게 레이블링해서 피할 수 있음.
        
    
    편향을 피하기 위해선 미리 대비
    
5. **낮은 예측력**
    
    가능한 많은 추가 특징 설계, 간접 데이터 소스 고려
    
6. **오래된 견본**
    
    실제로는 많은 시나리오에서 **개념 이동(concept drift)로** 인해 모델이 오류를 범하기 시작함
    
    **개념 이동(concept drift)** - 특징과 레이블의 통계적 관계가 근본적으로 변하는 것
    
    새로운 데이터에 대해 모델 성능이 감소하면 개념 이동을 고려
    
    오래된 견본을 제거하고 가장 최근 견본이 앞에 위치하도록 정렬. 모델 재교육에 필요한 최신 견본의 비율을 정의하는 하이퍼파라미터를 추가하고 조정
    
7. **특잇값**
    
    데이터 세트의 대부분의 견본과 달라보이는 견본. 유클리드 거리 같은 지표로 정함
    
8. **데이터 누출**

### 3. 좋은 데이터란?

1. 유익함
    
    모델링에 필요한 충분한 정보가 포함
    
2. 넓은 적용 범위
3. 실제 입력을 반영 - 운영 환경에서의 실제 입력 반영
4. 편향되지 않음
5. 피드백 루프의 결과가 아님
    
    피드백 루프: 어떤 시스템의 출력 결과가 다시 입력으로 되돌아가 다음 동작에 영향을 주는 순환 구조
    
    실제 환경을 즉시 반영해 성능 고도화, 환경 변화에 빠르게 대응 가능
    
    그러나 편향 증폭, 데이터 왜곡 
    
6. 좋은 데이터의 레이블은 일관됨
    
    불일치 되는 경우
    
    1. 사람마다 다른 기준으로 레이블링
    2. 클래스의 정의는 시간이 지남에 따라 바뀜 → 매우 유사한 특징 백터에 2개의 다른 레이블로 지정하는 상황 발생
    3. 사용자의 동기에 대한 오해 (사용자의 의도/동기를 추축해 라벨을 붙임)
7. 충분히 큼

### 4. 상호 작용 데이터 처리

**상호 작용 데이터(interaction data)** -  모델이 지원하는 시스템과 사용자 간의 상호 작용에서 수집할 수 있는 데이터

3가지 정보를 포함

1. 상호 작용의 맥락
2. 해당 맥락에서의 사용자 행동
3. 상호 작용의 결과

### 5. 데이터 누출의 원인

1. **목표가 특징의 함수인 경우** (ex. 인구 1인당 GDP으로 나라의 GDP를 예측하면 특징에 다 포함됨)
2. **목표가 특징에 숨어 있는 경우** - 특징에 목표가 숨어 있음
3. **미래를 반영하는 특징** - 예측 시점 이후에만 알 수 있는 정보를 입력으로 쓰는 상황

### 6. 데이터 분할

**훈련세트**: 훈련에 사용

**검증세트**: 최적의 하이퍼 파라미터 찾기

**테스트세트**: 결과 보고 등 성능 측정

**분할 조건**

1. 원시 데이터에 분할 적용
2. 분할 전에 랜덤화
3. 검증 세트와 테스트 세트는 동일한 분포를 따름
4. 분할 도중 누출 방지

검증/테스트셋에는 클래스별 최소 10개

- 분할 중 누출
    
    같은 사용자의 레커도가 훈련/테스트에 나뉘어 들어감 → 그룹 분할
    

### 7. 결측 속성 처리

일반적으로 제거, 결측 처리 알고리즘 사용, 대이터 대체 기술 사용

1. 데이터 대체 기술
    
    수치형속성 - 해당 속성의 **평균값**으로 대체
    
    정상적인 값의 **범위를 벗어난 값**으로 대체 → 결측 자체가 의미가 있을 때 주로 사용.
    
    범위 **중간값으로 대체**
    
    결측값을 회귀 문제의 **목표 변수로 사용**
    

### 8. 데이터 증강

1. **이미지 데이터 증강**
    
    뒤집기, 회전, 
    
    자르기(자르고 관심 부분이의 상당 부분 남아야 함),

### 9. 불균형 데이터 처리

훈련 데이터의 레이블 분포가 불균일함

소수에 해당하는 클래스 견본의 오분류에 대한 손실이 다수를 차지하는 클래서 견본의 오분류에 따른 손실과 동일하다면 알고리즘은 소수 클래스 견본을 포기할 가능성이 높다.

1. **오버샘플링** - 소수 클래스의 견본을 여러 개 복사해서 비중을 높임
    
    함성 소수 오버샘플링 기법(SMOTE), 적응적 합성 표본법(ADASYN)이 있음
    
2. **언더샘플링** - 다수 클래스의 일부를 훈련 세트에서 제거
    
    토멕 링크 - 경계에 바짝 붙어 있는 서로 다른 클래스의 최근접 이웃 쌍 → 다수 클래수 쪽을 제거
    
    군집 기반 언더샘플링
    
3. 하이브리드 전략

### 10. 데이터 샘플링 전략

- 단순 랜덤 샘플링
- 체계적인 샘플링(systematic sampling) - start에서 k간격으로 샘플 선택 → 전체 범위 샘플을 고를 수 있음, 패턴이 있으면 별로
- 계층화된 샘플링 - 데이터를 그룹으로 나눈후 각 그룹에서 랜덤하게 선택(그룹 크기에 비례해서).

### 11. 데이터 저장

데이터를 안전하게 유지하는것이 중요

- 데이터 버전 관리
    1. 버전관리 하지않음
    2. 훈련 시점의 스냅숏으로 버전관리(모델이 맍히 않고 자주 업데이트하지 않는 경우)
    3. 데이터와 코드 모두 버전관리
    4. 특화된 데이터 버전 관리 솔루션을 사용하거나 구축
- 문서화와 메타데이터
    
    데이터를 다른 사람이 이해하기 쉽도록 설명
    
- 데이터 수명 주기 문서 관리
