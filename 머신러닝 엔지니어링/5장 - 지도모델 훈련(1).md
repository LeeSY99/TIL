### 1. 모델 개발 시작 전

1. 스키마 적합성 검증
    
    **원본 데이터가 현재 데이터와 동일하지 않을 수 있음.**
    
    요인
    
    - 데이터를 드라이브나 데이터베이스에 보관하는 방법에 오류가 있음
    - 데이터를 읽는 방법에 오류가 있음
    - 다른 사람이 사용자에게 알리지 않고 데이터나 스키마를 변경했을 수 있음
2. **달성 가능한 성능 수준 정의**
    
    모델을 개선하려는 시도를 언제 중단해야 할지 결정
    
    몇가지 지침들
    
    - 너무 많은 노력, 수학이나 복잡한 논리 유도 없이 인간이 견본에 레이블링할 수 있다면 모델이 인간 수준의 성능을 달성할 수 있다
    - 레이블링 결정에 필요한 특징이 충분하면 모델이 거의 오류를 범하지 않을 것으로 예상할 수 있다
    - 입력 특징 벡터에 충분한 값이 있는 경우 오류를 거의 없앨 수 있다
    - 동일한 분류나 회귀 문제를 해결하는 프로그램이 있는 경우, 모델이 최소한 이 수준의 성능을 발휘할 것으로 기대할 수 있다. 데이터가 더 많으면 성능 개선할 수 있다
    - 모델과 유사한 다른 시스템을 관찰해 보고 성능을 개선할 방법을 찾아볼 수 있다
3. **성능 지표 선택**
    
    개발 시작 전 성능 지표를 하나 선택해서 여러 모델 비교하고 전체 상황 추적
    
4. **올바른 기준선 선택**
    
    개발 시작 전 문제에 대한 기준 성능을 설정하는 것이 중요. 기준선은 비교를 위한 기준점을 제공하는 모델이나 알고리즘
    
    **2가지 알고리즘**
    
    1. **랜덤 예측 알고리즘** - 훈련 견본에 할당한 레이블 모음에서 무작위성을 사용해 예측을 만드는 가장 기준모델. 
        - **분류**: 모델이 성능이 낮더라도 무작위로 예측한 것보다 성능이 높아야한다는 기준.
        - **회귀**: 타깃의 전체 분포 추정 후 샘플을 추정해 사용
    2. **제로 규칙 알고리즘**
        - **분류** - 훈련 세트에서 가장 많이 나온 클래스로 예측 - ex) 양성 클래스가 60% 음성 40%이면 정확도 60%
        - **회귀** - 훈련세트의 타깃의 평균(중앙값)으로 예측
5. **데이터를 세 개의 세트로 분할**
    
    **훈련, 검증, 테스트**
    
    검증셋과 테스스텟은 **동일한 통계 분포**를 따라야 함
    
    모델이 배포될 운영 환경의 데이터와 매우 유사한 분포에서 검증, 테스트 데이터를 추출해야 함
    
6. **지도학습의 전제 조건**
    1. 레이블링된 데이터 세트가 있다
    2. 데이터를 훈련,검증,테스트 3가지 부분집합으로 분할했다
    3. 검증 세트와 테스트 세트의 견본은 통게적으로 유사하다
    4. 특징을 설계하고 훈련 데이터만 사용하여 결측값을 채웠다
    5. 모든 견본을 수치형 특징 벡터로 변환했다
    6. 하나의 숫자를 반환하는 성능 지표를 선택했다
    7. 기준선이 있다

### 3. 학습 알고리즘 선택

1. 학습 알고리즘의 주요 특성
    - **설명 가능성** - 비전문가 청중에게 모델 예측에 대한 설명이 필요한가
        
        (블랙박스[내부를 이해하기 힘듬] → 심층 신경망, 앙상블 모델, 내부 설명 가능 → k-nn, 선형회귀, 의사 결정 트리)
        
    - **인-메모리와 메모리 부족(out-of-memory)** - 전체 데이터 세트를 메모리에 모드 로드할 수 있나
        
        그렇지 않다면 점진적 학습 알고리즘 선택
        
    - **특징과 견본 수** - 데이터 세트에 몇 개의 훈련 견본이 있는지, 몇 개의 특징이 있는지
    - **데이터의 비선형성** - 데이터를 선형적으로 분리할 수 있는지?
        
        그렇다면 선형 커널이 있는 SVM, 선형회귀, 로지스틱 회귀
        
        그렇지 않다면 심층 신경망, 앙상블 모델
        
    - **훈련 속도** - 학습 알고리즘으로 모델을 구축하는 데 시간이 얼마나 걸리는지, 데이터가 업데이트 되면 얼마나 자주 재훈련 해야하는지
        
        신경망은 오래걸리고, 간단한 알고리즘은 빠름
        
        gpu로 속도 향상
        
    - **예측 속도** - 모델이 얼마나 빨리 예측하는지
    
    검증 세트를 통해 여러 후보 알고리즘을 하이퍼파라미터로 테스트해서 좋은 것을 선택함
    
2. **알고리즘 스팟 검사**
    
    주어진 문제에 대한 학습 알고리즘의 후보 목록을 추리는 것
    
    - 인스턴스 기반, 커널 기반, 얕은 학습, 딥러닝, 앙상블과 같이 다양한 독립적 기반의 알고리즘 선택
    - 가장 민감한 하이퍼파라미터에 대해서는 서로다른 3~5개의 값으로 실험
    - 모든 실험에 동일한 훈련/검증 분할 사용
    - 학습 알고리즘이 결정적이지 않은 경우, 여러번 실험한 다음 결과 평균
    - 다음에 유사한 문제가 있으면 이 정보를 사용

### 5. 모델 성능 평가

1. **회귀 분석의 성능 지표**
    
    **MSE(mean squared error), MAE(median absolute error), ACPER(almost correct predictions error rate, 매우 정확한 예측 오차율)**
    
    잘 적합된 회귀 모델은 평균 모델(훈련 데이터의 평균값으로 예측)보다 더 잘 fit해야 함.
    
    특잇값(표본에서 멀리 떨어진)값이 있으면 MSE보단 MAE 적용
    
    **ACPER** - 혀용 오차 범위안에 들어오지 못한 예측의 비율
    
2. **분류의 성능 지표**
    - 정밀도precision - 재현율recall
    - 정확도
    - 비용에 민감한 정확도
    - ROC곡선 아랴 영역(AUC)
    
    **confusion matrix** - 모델이 다양한 클래스에 속하는 견본을 예측하는 데 얼마나 성공적인지를 요약한 표
    
    **TP(true positive)** - 실제로 참인데 모델도 참으로 예측
    
    **FP(False positive)** - 실제로 거짓 모델은 참으로 예측
    
    **TN(True Negative)** - 실제로 거짓 모델도 거짓으로 예측
    
    **FN(False Negative)** - 실제로 참인데 모델이 거짓으로 예측
    
    **정밀도(precision)** 전체 참 예측수에 대한 진짜 참 TP/(TP+FP)
    
    **재현율(recall)**  전체 참 견본 수에 대한 참 TP/(TP+FN) 
    
    → 이진 분류에 대한 정밀도와 재현율을 이용해 다중 클래스 분류 모델도 평가 가능. **평가할 클래스는 참, 나머지를 거짓으로 간주하여 평가**
    
    최적화 및 만족화 기술(optimizing and satisficing technique) **- 재현율과 정밀도로 어떤 모델이 나은지 비교하기 힘듬**(어떤 모델은 재현율이 높고 어떤 모델은 정밀도가 높은 경우) → **한가지 최소 임계값을 설정한 다음 넘는 모델 중 다른 지표로 비교**
    
    **F-score.** f1 = 2*(재현율*정밀도)/(재현율+정밀도)
    
    **클래스마다 중요도가 다를 때** → 비용에 민감한 정확도
    
    **불균형 데이터** → 클래스별 정확도 지표
    
    **ROC곡선 (예측점수/확률**) 을 내는 분류 모델을 평가
    
    **참양성률(TPR)[재현율]:** TP/(TP+FN) 
    
    **거짓 양성률(FPR)[잘못 예측된 음성 견본 비율]** = FP/(FP+TN)
    
    ROC곡선 아래 영역(AUC)가 클수록 좋음
    
3. **순위를 위한 성능 지표**

### 6. 하이퍼파라미터 조정

일부는 훈련 속도에 영향을 주지만 가장 중요한 하이퍼파라미터는 편향과 분산 간, 그리고 정밀도와 재현율 간의 절충(tradeoffs)함

1. **그리드 탐색(grid search)**
    
    하이퍼 파리미터의 범위가 크지 않을 때
    
    하이퍼파라미터 값의 쌍으로 파이프라인 구성 → 훈련 → 성능 계산
    
    ex) n_components = [2,5,10], C = [0.1,10,100] 조합
    
2. **랜덤 검색(random search)**
    
    탐색할 하이퍼 파리미터 값을 주지 않고 랜덤하게 샘플링
    
3. **무작위-미세한 검색(coarse-to-fine search)**
    
    그리드 + 랜덤 검색의 조합
    
    랜덤검색으로 가능성이 높은 영역을 찾고 영역 안에서 그리드 탐색
    
4. **기타**
    1. 베이지안 기술(bayseian techniques) - 다음에 평가할 값을 선택하기 위해 과거 평가 결과를 사용.
    2. 기울기(gradient)기반, 진화(evolutionary)최적화 기술 다양함
5. **교차 검증**
    
    검증세트가 있을 때
    
    하이퍼 파라미터 값을 고정하고 훈련 세트를 동일 크기로 분할.
    
    분할한 영역 하나는 검증세트로 나머지는 훈련세트로 사용해서 모든 데이터가 훈련과 검증에 참여하게끔 함

### 8. 편향-분산 간 절충(bias-variance tradeoff)

1. **과소적합**
    
    모델이 훈련 데이터 레이블을 잘 예측할 수 있다면 편향이 낮다(low bias)라고 함.
    
    반면 모델이 훈련 데이터에서 너무 많은 예측 실패를 하면 편향이 높거나(high bias) 모델이 학습 데이터에 과소적합(underfit)되었다고 함
    
    **가능한 이유**
    
    1. 데이터에 비해 모델이 너무 간단함
    2. 특징에 유익한 정보가 충분하지 않다
    3. 정규화를 너무 많이 한다
    
    **→ 해결책**
    
    1. 좀 더 복잡한 모델로 시도
    2. 예측력이 높은 특징 설계
    3. 더 많은 데이터 추가
    4. 정규화 축서
2. **과적합(overfitting)**
    
    일반적으로 훈련 데이터 레이블은 잘 예측하지만 홀드아웃데이터(테스트,검증) 데이터에 대해서는 잘 예측하지 못함
    
    높은 분산(high variance)이라고도 함 → 훈련 세트의 작은 변동에도 민감하게 반응 → 조금만 훈련 셋이 다르게 샘플링되어도 결과가 크게 달라짐
    
    **가능한 사유**
    
    1. 모델이 데이터에 비해 너무 복잡함. 큰 의사결정 트리나 깊은 신경망
    2. 특징이 너무 많고 훈련 견본 수는 적다
    3. 충분히 정규화가 되지 않음
    
    **→ 해결책**
    
    1. 더 간단한 모델 사용.
    2. 데이터 셋에서 뽑은 견본의 차원을 줄임
    3. 훈련 데이터 추가
    4. 모델 정규화
3. **절충**
    
    실제로 분산을 줄이려고 하면 편향이 증가하고 반대의 경우도 마찬가지임. 이를 잘 절충
    
    **솔루션 영역** - 과소적합 되지 않고 동시에 과대적합이 되지안흔 훈련 오차와 홀드아웃 오차가 둘다 낮은 영역
    
    - 모델의 복잡도를 증가시겨 편향 줄임
    - 분산을 줄이기 위해 모델을 더 단순하게 만듦
    
    위 내용 둘중 하나를 수행.
    

### 9. 정규화

학습 알고리즘이 덜 복잡한 모델을 훈련하도록 강제하는 방법에 대한 포괄적인 용어

**탄력적 그물 정규화**

**L1(lasso) 정규화** - 희소 모델 생성 → 매개 변수를 0으로 변환

**L2(ridge) 정규화 -** 매개변수의 크기를 줄임 → 영향을 덜 받게
