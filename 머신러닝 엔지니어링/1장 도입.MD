# 1장 - 도입

### 표기법 및 정의

1. 자료구조
    - 스칼라 - 단순한 수치(numerical value). 변수는 기울임꼴로 표시
    - 벡터 - 속성(attributes)라고 하는 스칼라 값의 순서가 있는 목록. 굵은 글꼴로 표시\
    - 행렬 - 행과 열로 구성된 숫자의 2차원 배열
    - 집합 - 순서가 없고 중복이 없는 요소의 모음
2. 머신러닝이란?
    
    어떤 현상에서 얻을 수 있는 **견본(example)**모음을 이용해서 유용한 알고리즘을 구축하는 것
    
    **견본(example)**은 자연에서 얻거나 사람이 직접 만들거나 다른 알고리즘을 통해 생성할 수 있음
    
    **머신러닝** (데이터 셋 수집 → 해당 데이터 세트로 통계 모델을 알고리즘적으로 훈련)
    
    - **지도학습**
        
        지도학습에서 데이터 분석가는 **레이블링된 견본**으로 작업.
        
        **특징 벡터(feature vector)** - n개의 요소 중 각 요소
        
        **벡터**는 1차원 배열로 표현하고, **인덱싱 값**으로 순서가 지정된 **시퀀스**를 나타냄. 이때 시퀀스의 길이를 **차원**이라고 함
        
        **레이블(label)** - **유한한 클래스**나 **실수** 또는 좀 더 복잡한 구조인 **벡터, 행렬 , 트리, 그래프**에 속하는 하나의 요소를 나타냄
        
        **분류(classification)** - 클래스를 예측하는 문제. 서로 다른 클래스의 견본을 구분하는 선(초평면hyperplane)을 찾음
        
        **회귀(regression)** - 실숫값을 예측하는 문제. 훈련 견본을 밀접하게 따라가는 선 또는 초평면을 찾음
        
        목표(target) - 지도학습된 모델이 예측해야 할 값
        
    - **비지도 학습**
        
        데이터 셋: 레이블이 없는 견본 모음.
        
        특징 벡터 x를 입력으로 받아서 다른 벡터로 변환하거나 실제 문제를 해결하는 데 사용할 수 있는 값으로 변환하는 모델을 만드는 것.
        
        **군집화(clustering**) - 모델이 데이터 세트의 각 특징 벡터에 대한 군집ID 반환.
        
        **차원 축소(dimensionality reduction)** - 입력보다 차원이 낮은 특징벡터 출력
        
        **이상치 검출(outlier detection)** - 입력 특징 벡터가 데이터 세트의 ‘일반’ 견본과 어떻게 다른지를 나타내는 실수의 값. (z-score[각 특징이 평균에서 몇 표준편차 만큼 떨어졌는지] 등등 여러가지가 있음(거리 기반, 밀도 기반) 등)
        
    - **준지도 학습**
        
        레이블링된 견본과 레이블링되지 않은 견본이 모두 있음(보통 안된게 더 많음)
        
        목표는 **지도학습과 동일**하지만, 레이블링이 안된 많은 견본을 추가해 학습 알고리즘이 더 나은 모델로 개선할 수 있도록 하는 것을 보통 기대함
        
3. **데이터/머신러닝 용어**
    - 직접/간접적으로 사용하는 데이터
        
        ex) 단어 → 임베딩 → 특징벡터 - 직접, 단어사전 - 간접
        
    - 원시 데이터/깔끔한 데이터
        
        원시 데이터(raw data): 가공하지 않은 자연 형태의 개체 모음(워드 문서, jpeg파일)
        
        깔끔한 데이터(tidy data) - 분석, 시각화, 모델링이 바로 가능한 깔끔한 표 형태
        
    - 훈련 및 홀드아웃 세트
        
        **홀드아웃 세트** - **검증, 테스트 세트**를 통톨어서 부름
        
        **데이터 누출**: 검증, 테스트 세트가 학습 알고리즘에 노출된 상황
        
    - 일반적으로 머신러닝에서의 기준점은 휴리스틱, 간단한 요약 통계, 랜덤화 또는 매우 기본적인 머신러닝 알고리즘을 기반으로 문제를 해결하는 간단한 알고리즘이다
        - 기준점: 아주 단순한 방법으로 먼저 세워 보는 출발선
            
            문제를 최소 노력으로 푸는 가장 단순한 방법. 성능 하한선
            
        - 목적: 복잡한 모델이 정말 쓸모가 있는가?
        - 휴리스틱: 규칙 몇개로 찍는 방법(스팸메일에서 제목에 특정 내용이 들어가면 스팸 분류, 이상치: 온도 80도 넘으면 경보 발생 등)
        - 간단한 요약 통계: 평균, 중앙값 같은 통계값으로 예측
        - 랜덤화: 무작위로 뽑거나 섞어서 만드는 기준 (클래스 비율에 맞춰 무작위 예측)
        - 매우 기본적인  ML 알고리즘: 로지스틱 회귀 등등을 이용해 특징공학 없이 빠르게 학습
    - **머신러닝 파이프라인**
        
        초기 상태부터 모델 마무리까지 데이터 세트에 대해 수행하는 작업
        
        데이터 분할, 결측 데이터 대체, 특징 추출, 데이터 증강, 클래스 불균형 감소, 차원 감소, 모델 훈련 등
        
    - **초매개변수(hyperparameter), 매개변수(parameter)**
        
        **초매개변수(hyperparameter):** 머신러닝 알고리즘이나 파이프라인의 입력으로 모델의 성능에 영향을 줌. 
        
        학습 데이터에 포함되지 않고 훈련을 통해 학습하지 않음.
        
        **매개변수(parameter):** 학습 알고리즘을 통해 훈련하는 모델을 정이하는 변수. 훈련 데이터를 통해 학습 알고리즘이 직접 갱신함
        
    - 분류와 회귀
        
        분류: 레이블이 없는 견본에 레이블을 할당
        
        휘귀: 레이블이 없는 견본에 실제 값을 예측
        
    - 모델 기반/ 인스턴스 기반
        
        대부분의 지도학습 알고리즘은 모델 기반
        
        인스턴스 기반: 전체 데이터 세트를 모델로 사용(kNN)
        
4. **머신러닝을 사용해야 할 때**
    1. 문제가 복잡해서 코딩으로 해결할 수 없을 때
        
        스팸 검출: 스팸을 구별하는 로직을 구현하는 코드를 작성하는 것은 고려해야할 요소가 너무 많아 유지보수 어려움.
        
    2. 문제가 지속적으로 변할 때
        
        일부 문제는 시간이 지남에 따라 지속적으로 변할 수 있으므로 코드를 정기적으로 업데이트 해야하는데 매우 부담됨
        
    3. 지각 문제일 때
        
        이미지에서 물체 인식, 소리에서 음성 인식 등 일반 규칙으로 감당하기 어려운 복잡성이 있음.
        
    4. 연구되지 않은 현상일 때
        
        이론 없이도 패턴 학습이 가능해서 유용할 수 있음
        
    5. 문제의 목적이 간단
    6. 비용 효율적
        - 데이터 수집, 준비, 정제
        - 모델 훈련
        - 모델을 서비스하고 모니터링하기 위한 인프리 구축,운영
        
        을 고려하여 결정
        
5. **머신러닝을 사용하지 말아야 할 때**
    1. 시스템의 모든 조치나 결정이 설명 가능해야 한다
        
        ML(특히 딥러닝)은 내부가 복잡해서 결정 근거를 완전하게 설명하기 어려울 수 있음.
        
    2. 유사한 상황에서 과거 동작과 비교하여 시스템 동작의 모든 변화를 설명할 수 있어야 한다
        
        모델 업데이트나 데이터 드리프트로 미세한 변화가 생기면 “왜 바뀌었는지” 추적이 까다로움.
        
    3. 시스템에서 발생하는 오류에 따른 비용이 높다
        
        작은 오판이 큰 손실/안전사고로 이어지는 경우
        
    4. 가능한 한 발리 시장에 진출하기를 원한다
        
        ML은 데이터 수집·라벨링·검증·배포 파이프라인에 시간이 든다.
        
    5. 올바른 데이터를 얻는것이 너무 어렵거나 불가능하다
        
        라벨이 없거나 품질이 낮고, 개인정보/현장 제약으로 수집 불가. 쓰면 쓸수록 오판 위험.
        
    6. 기존 방식의 소프트웨어 개발을 통해 저렴한 비용으로 문제를 해결할 수 있다
        
        ML은 인프라/모니터링/재학습 비용이 숨겨져 있다
        
    7. 간단한 휴리스틱이 합리적으로 잘 작동한다
    8. 어떤 상황에서 너무 많고 다양한 결과가 발생하지만 이를 표현할 충분한 견본을 얻을 수 없다
        
        출력 공간이 거대하면 학습에 필요한 데이터가 폭증
        
    9. 시간이 지남에 따라 자주 개선할 필요가 없는 시스템을 구축한다
    10. 모든 입력에 대한 예상 출력으로 전체 룩업을 수동으로 채울 수 있다
