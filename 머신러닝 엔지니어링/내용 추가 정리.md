- 머신러닝 프로젝트 주기
    
    **문제 정의 → 데이터 준비 → 모델 개발/검증 → 배포 → 모니터링/개선**의 반복 루프
    
    ML 시스템이 아이디어로 시작해 실제 운영되고, 성능이 떨어지면 다시 개선/재학습되거나 퇴역할 때까지의 전 과정
    
    - 문제정의 →
    - 데이터 수집/접근 → EDA → 기준선(데이터 엔지니어) →
    - 특징/레이블 설계 → 모델 훈련/튜닝 → 검증/평가 → [분석가, ml엔지니어?]
    - 배포 → 모니터링/운영 → 유지보수 →  [MLOps]

- 머신러닝 프로젝트가 실패하는 이유 7가지
    - 숙련된 개발자 부족
        - 실무 경험이 많이 없는 경우
        - 데이터와 머신러닝 모델을 적절하게 처리하는 데 필요한 전문지식 부족
    - 경영진의 지원 부족
        - 높은 불확실성 속에서 여러 실험을 진행 → 실패하는 경우가 많음 → 리더들은 시간과 자원 낭비로 인식
        - 개발자들이 고위 경영진에게 실험의 결과와 어려운 점을 잘 전달하지 못함. 기술에 대한 전문지식이 다르기 때문에 잘못 이해해서 실패로 이해한 경우가 있음
        
        → 성공하는 조직에서 개발/과학자는 이해하기 쉽게 설명할 수 있어야 하고. 최고 관리자는 관련 기술을 알고 있음
        
    - 데이터 인프라 부족
        - 데이터의 품질 매우 중요
        - 데이터 인프라는 양질의 데이터를 얻을 수 있는 방법 제공
        - 운영 환경에 배포되면 유사한 품질의 데이터를 사용할 수 있는 인프라를 제공해야함
    - 데이터 레이블링의 어려움
        - 데이터 라벨링거나 레이블링 도구 개발에 상당한 시간 소요
        - 아웃소싱 하지만 품질 문제 가능성
    - 고립된 조직과 협업 부족
        - 데이터는 종종 소유권, 보안 제약 조건이 다른 조직에서 다른 형태로 보관하고 있음
        - 신뢰와 협업이 부족하면 다른 부서의 데이터에 접근할 때 마찰 발생
        - 불신의 대표적인 원인은 과학자가 사용하는 도구와 접근 방식에 대한 엔지니어의 이해 부족과 소프트웨어 엔지니어링 우수 사례와 디자인 패턴에 대한 과학자의 지식 부족
    - 기술적으로 실행 불가능한 프로젝트
        - 보통 머신러닝 프로젝트의 높은 비용 떄문에 투자 회수를 위해 조직이나 제품을 완전히 바꾸거나 비현실적인 수익이나 투자를 제시하는 등 야심찬 목표를 세울 수 있음
        - 이렇게 되면 너무 오래 걸림 → 일부 참여자는 관심을 잃거나 조직을 떠날 수 있음
        - 초기에는 범위를 쉽게 정할 수 있는 달성 가능한 프로젝트의 집중하고 간단한 비즈니스 목표를 세워야 함
    - 기술팀과 비즈니스팀 간의 소통 부족
        - 많은 프로젝트는 기술팀이 비즈니스 목표에 대한 명확한 이해 없이 시작되는 경우가 많음
        - 비즈니스 목표에 대한 지속적인 피드백이 없고 과하갖는 종종 초기수준의 모델 성능에 도달한 다음 그들이 유용한 진전을 이루고 있는지 추가 노력이 그만한한 가치가 있는지 확실히보여주지 못함 → 시간가 자원이 들었지만 비즈니스팀이 결과를 받아들이지 않음 → 프로젝트 보류
