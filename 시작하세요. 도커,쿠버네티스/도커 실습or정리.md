서버란? 하드워어와 하드웨어에서 실행하는 소프트웨어까지 모두 포함

클라이언트의 요청에 대한 결과를 제공.

종류

파일서버, db서버, 웹서버(https, css, js를 받음), 웹 애플리케이션 서버[WAS] (프로그래밍 언어로 개발된 백엔드 앱을 실행)

---

**서버 운영 방식**

1. 베어메탈(Baremetal): 서버를 구입하고 os설치하고 여러 sw 실행 [비효율]
2. 하이퍼바이저(Hypervisor): os의 프로그램으로 실행해서 가상화 관리. 가상환경을 만들 때 메모리를 차지하고 있다가 실행시키면 cpu와 메모리 등을 사용
    
    물리 서버에 설치되는 os: 호스트 os
    
    호스트 os의 자원을 격리해 새 os 실행(게스트 os) : 가상머신이라고 부름
    
    서로 다른 os의 시스템 콜을 통역해주는 느낌
    
    게스트os커널, 호스트 os 커널 2개가 있어 느린편
    
3. 컨테이너(Container): 하이퍼바이저보다 가볍고 빠름
    
    LXC(LinuX Containers) 에서 시작됨. **커널의 자체 기능만 사용해 격리된 공간을 만들** 수 있음.
    
    네임스페이스:  프로세스, 하드드라이브, 네트워크, 사용자, 호스트네임 처럼 리소스를 나누는 기준
    
    Cgroups: 프로세스가 사용하는 메모리 cpu 하드디스크 네트워크 밴드위처럼 리소스의 사용량 분배
    
    하나의 커널을 사용해 빠름
    

→ 컨테이너 가상화가 다른 2가지 가상화 보다 빠르다 그 이유는 컨테이너 가상화는 별도의 게스트 os 없이 호스트 os 커널을 사용하기 때문.

---

**가상화** - 실제로 존재하지 않는 컴퓨터를 사용하게 함 → 하나의 컴퓨터에서 여러개의 컴퓨터 실행할 수 있음 → 물리적인 컴퓨팅 환경 내부에서 논리적인 컴퓨팅 환경을 만들 수 있는 기술

한 컴퓨터 안에 여러개 앱을 실행중일 때 하나의 앱에서 오류가 발생하거나, 자원 사용량이 증가하면 다른 앱에도 영향을 미칠 수 있음 → 운영중인 서비스가 장애를 겪으면 치명적 → 하나의 os에서 운영하는 것은 피하는게 좋음

가상화 기술로 여러개의 os를 만들 수 있고 리소스를 분배할 수 있음. 서로 프로그램이 영향을 줄 수 없음

낮은 성능 여러개보단 큰 거 하나가 효율적

**도커 아키텍처(클라이언트-서버 모델)**

클라이언트(사용자): 사용자의 명령 전달

도커 데몬(서버): 호스트 os에서 계속 실행되며 클라이언트의 요청을 받아 컨테이너, 이미지를 관리함.

API : 두 상호 관계에서 주고 받는 데이터의 약속

사용자가 CLI 를 통해 명령어로 전달하면 도커 데몬에 API 형태로 전달

**이미지와 컨테이너**

서버에서 프로그램을 실행하기 위해선 소프트웨어적으로 3가지가 필요

1. os
2. 프로그램이 실행하기 위해 필요한 구성 요소
3. 실행할 프로그램

nginx 설치할때 필요한 구성요소 설치 따로 안하고 이미지로만 지정했는데 가능한 이유는?

→ 이미지는 파일 시스템의 특정 순간을 저장해놓은 압축 파일.

소프트웨어뿐만 아니라 소프트웨어가 실행하기 위해 필요한 모든요소를 준비해 압축

이미지 메타데이터: 이미지에 대한 정보를 저장

메타데이터 cmd와 env등등 **덮어쓰기** 가능

컨테이너 라이프사이클

생성, 실행, 일시정지(paused)[마지막 상태에서 재시작, 메모리는 그대로 할당], 종료(stopped)[메모리 cpu 할당 끊김]

---

**이미지 레지스트리**

도커 허브같은데서 이미지를 저장하고 공유하는 공간

- 이미지 공유, 검색, 버전 관리, 보안, 파이프라인(DevOps 기능과 연계해 이미지 업로드하면 자동 배포) 등의 작업을 할 수 있다
- 로컬 스토리지, 온라인(퍼블릭 레지스트리, 프라이빗 레지스트리) 3가지 장소에 저장할 수 있음

이미지 이름 규칙 : 레지스트리주소/프로젝트명/이미지명:이미지태그

레지스트리 주소(docker.io 기본값)

프로젝트명: 가입 아이디 기본값, 비워놓으면 공식 인증된 이미지가 다운됨

태그: 버전(latest - 기본값)

- docker pull 이미지이름 → 로컬에 이미지 다운
- docker tag 기존이미지이름 추가할이미지이름 → 이미지이름 추가
- docker push 이미지이름 → 이미지 레지스트리에 업로드

중요! : 도커를 사용하면 모두 동일한 환경에서 작업이 가능해 환경의 차이에서 나오는 문제들을 해결할 수 있다.

**이미지 빌드**

이미지는 레이어로 구성되어 저장공간을 효율적으로 사용함. 변경사항에 유연하고 중복 부분에 대해 재활용이

이미지 레이어는 직전 단계의 레이어에서 **변경된 것을** 저장.

같은 변경이 일어난 레이어는 공유하여 재사용

1. 이미지로 컨테이너를 실행하면 컨테이너 레이어(읽기/쓰기) 추가
    - 같은 이미지로 여러 컨테이너 생성해도 하나의 이미지를 공유해 읽어옴 → 컨테이너 생성 속도 빠름
2. 로그가 쌓이거나 컨테이너 실행 중에 변경사항은 새 레이어(컨테이너 레이어)에 추가

**CoW(Copy-on-Write)전략**: 다음 레이어에서 이전 레이어의 특정 파일을 수정할 때 해당 파일의 복사본을 만들어 변경사항 적용

**Immutable Layers**: 각 레이어는 변하지 않음 → 이미지의 일관성 유지, 여러 컨테이너에서 안전하게 공유

**Caching**: 레이어를 캐시해 이미 빌드된 레이어를 재사용 → 이미지 빌드 시간을 크기 줄여줌
