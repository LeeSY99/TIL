JOIN이 여러 테이블을 수평으로 붙여서 만드는 기술이라면, UNION은 여러 개의 결과 집합을 수직으로 붙여서 만드는 기술

- 합치고 중복되는 행은 중복을 제거해서 고유한 값을 남김
- 중복을 허용해야하거나, 중복이 없다는 걸 알아서 중복 검사를 안해도 되면 → UNION ALL

---

### UNION ALL

- UNION 과의 차이는 중복 처리 여부

### 성능

- UNION ALL이 UNION 보다 훨씬 빠름
    - 보통 전체 결과를 정렬한 다음, 서로 언접한 행들을 비교하여 중복을 찾아내는 과정을 거침

---

### UNION 정렬

UNION ALL 또는 UNION을 사용하고 최종 결과에 대해 정렬을 적용할 수 있음. 이때 ORDER BY 절의 위치가 중요

- UNION 연산의 가장 마지막에 한 번만 사용해야 함
    - 각 SELECT 문 안에 ORER BY를 사용하면 에러가 나거나 예상과 다른 결과가 나올 수 있음
- UNION 연산의 ORDER BY 절에서는 첫 번째 SELECT 문의 컬럼이름이나 해당 컬럼의 별칭만 사용할 수 있음
    - UNION 결과 집합 컬럼 이름이 첫 번째 SELECT 문을 따르기 때문
