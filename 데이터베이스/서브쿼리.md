**JOIN 만으로 한 번에 답하기 어려운 여러 단계를 거쳐야 하는 문제들을 풀 때 활용**

EX) 평균 가격보다 높은 상품 리턴

- 평균을 구하는 쿼리 1번
- 그 평균보다 큰 상품을 구하는 쿼리 1번
- 총 2번의 쿼리를 사용하는데 → 서브쿼리로 하나의 작업으로 묶기 가능

### 2번의 쿼리를 거칠 때의 단점

- **번거로움**: 매번 첫 쿼리의 결과를 복사해서 두 번째 쿼리에 넣어야 함
- **오류에 취약**: 데이터가 실시간으로 추가되거나 변경될때 (1단계 쿼리를 수행하고 2단계 쿼리를 실행하는 짧은 순간에 변할 수 있음) → 잘못된 데이터를 조회하게 됨

### 서브쿼리

- 하나의 쿼리 문 안에 또 다른 SELECT 쿼리. 메인 쿼리가 실행되기 전에 () 안에 있는 서브쿼리가 먼저 실행
- 다양한 위치에서 다양한 역할을 수행

### 스칼라 서브쿼리 (하나 행, 하나 컬럼)

- 단일 컬럼, 당일 행 서브쿼리 (가로 세로 1개의 값 → 값 하나)
- 단일 행 비교연산자(=, >, <, ≥, ≤ <>) 등과 함께 사용할 수 있다
- **서브쿼리의 결과가 무조건 하나의 행만 반환해야 함**

### 다중 행 서브쿼리 (여러 행, 하나 컬럼)

- 여러개의 행을 반환하는 서브쿼리를 필요로 할 때가 있음
- IN, ANY, ALL 과 같은 **목록을 다룰 수 있는 연산자** 필요
- IN 연산자 : WHERE 컬럼명 IN (값1, 값2, …) → 특정 컬럼의 값이 괄호 안에 하나라도 있으면 TRUE 반환
- ANY, ALL 연산자 : 주로 >, < 와 같은 비교 연산자와 함께 사용
    - > ANY (서브쿼리): 서브쿼리가 반환한 결과 값 중 어느 하나보다 크면 참. (최소값보다 크면 참)
    - > ALL (서브 쿼리): 서브쿼리가 반환한 결과 값 모두보다 커야 함. (최대값보다 크면 참)
    - < ANY (서브쿼리): 최대값보다 작으면 참
    - < ALL (서브쿼리) : 최소값보다 작으면 참
    - = ANY (서브쿼리) : IN과 동일한 의미. 목록 중 어느 하나와 같으면 참
- ANY, ALL 보단 집계함수(MIN, MAX)가 보통 더 직관적

---

### 다중 컬럼 서브쿼리

메인 쿼리의 WHERE 절에서 여러 컬럼을 동시에 비교할때 유용

- WHERE (user_id, status) = (SELECT user_id, status) 이런 식으로 사용
- = 연산자를 사용할 때는 서브 쿼리의 결과가 **반드시 하나의** 행이어야 한다
- 여러 행이라면 IN 연산자를 사용한다

### 상관 서브쿼리

서브쿼리가 메인 쿼리에서 현재 처리 중인 행의 특정 값(ex 카테고리 명)을 알아야 계산을 수행할 수 있을 때 사용. → 각각의 행마다 비교대상?(서브쿼리) 이 달라지는 상황에서 사용

- 비상관 서브쿼리는 서브쿼리가 딱 1번 실행되고 그 결과가 메인 쿼리에 사용됨
- 상관 서브쿼리
    - 메인 쿼리가 먼저 행을 읽음
    - 읽혀진 행의 값을 서브 쿼리에 전달하고 서브쿼리 실행
    - 서브 쿼리의 결과를 이용해 메인쿼리의 WHERE 조건을 판단
    - 메인 쿼리의 다음 행을 읽고 위 과정 반복
- 메인 쿼리의 테이블이 서브쿼리의 테이블에서도 사용되는 것을 말함
- 서브쿼리의 테이블이 클땐 IN 보다 EXISTS가 효율적인 방법
    - IN도 좋지만 테이블이 클 땐 성능 문제 가능성
    - EXISTS는 서브쿼리가 반환하는 결과값에는 관심이 없고, 서브쿼리의 결과가 하나라도 존재하는지 여부만 체크
- 상관 서브쿼리와 성능
    - 대부분 JOIN으로 동일한 결과를 얻을 수 있다
    - 데이터베이스 옵티마이저가 JOIN을 더 효율적으로  처리하는 경우가 많음
    - 성능 이슈가 있다는 것을 인지하고 JOIN으로 표현하기 복잡하거나 EXIST를 통해 효율적인 실행이 가능할 때 적절하게 사용하는 것이 중요
