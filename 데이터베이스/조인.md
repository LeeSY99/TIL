### 조인이 필요한 이유?

- 해당 테이블에 없는 정보 (id가 있는데 누가 이 id인지 알고싶다. 그런데 이 테이블에는 이름이 없다). 분리해서 저장하고 필요할 때만 합친다.
- 그렇다면 한 테이블에 다 넣으면 안되나? 굳이 나눠서 저장하는 이유가 뭔가?
    1. 데이터 중복 - 한 고객이 주문을 100번 했다면 그 고객의 이름, 이메일, 주소 등 100번이나 불필요하게 저장됨
    2. 갱신 이상(update anomaly) - 한 고객이 이메일 주소를 변경했다면 그 고객이 주문한 100개의 데이터를 모두 찾아서 이메일 변경해야함. 실수로 하나라도 누락된다면 일관성이 깨져 어떤 정보가 진짜인지 모르게 됨
    3. 삽입 이상(insertion anomaly) - 새 상품이 추가됐을 때 주문자가 없으면 테이블에 넣을 수 없다.
    4. 삭제 이상(deletion) - 딱 1번만 주문한 사람이 있다고 치면, 이를 삭제하게 되면 이메일, 주소 등 고객 정보까지 잃게 됨
    5.  정규화라는 과정을 거쳐 설계함
- 정리하자면 데이터를 저장할 때 중복저장, 삽입, 삭제 갱신 이상의 이슈로 분리해서 저장하고 이를 필요할 때 합치기 위해 join을 사용한다.

### 내부 조인

두 테이블을 연결할 때 양 테이블에 모두 공통으로 존재하는 데이터만을 결과로 보여줌

```sql
SELECT 칼럼1, 칼럼 2
FROM 테이블A
INNER JOIN 테이블B ON 테이블A.연결컬럼 = 테이블B.연결컬럼
WHERE 조건;
```

순서: join으로 합침 → where 필터링 → select 칼럼 추출 

- 실무에서는 어디 테이블의 필드인지 명시하는 것이 가독성을 높이고 컬럼의 소속을 파악하기 쉽기 권장
- 쿼리 최적화기: 데이터베이스 내부에서는 쿼리를 더 효율적인 방식으로 실행. 결과는 같음

**조인과 집합**

- 내부 조인은 두 테이블의 교집합을 찾는 것과 같다

→ 어느 한쪽에만 데이터가 존제하는 경우에는 결과에 포함시키지 않고 양쪽 모두에 연결고리가 있는 데이터만을 짝지어 보여줌

**내부조인과 조인방향**

- 내부조인은 양방향. A→B로 조인할 수 있다면 B→A로 조인 가능하고 결과는 같다

**그럼 조인 순서는 언제 중요할까?**

- 쿼리를 읽는 사람의 입장에서 어떤 데이터가 중심이 되는지에 따라 순서를 정하면 가독성 향상

**테이블 별칭(Alias) → 가독성을 높임**

- 테이블이름 (AS) 별칭. AS 보통 생략
- 컬럼 별칭은 AS 사용.
    - 어떤 것이 컬럼이름이고 어떤 것이 별칭인지 즉시 파악하기 힘들기 때문
        - ex) SELECT salery * 12 annual_salary → SELECT salery * 12 AS annual_salary
