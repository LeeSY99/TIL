### 조인이 필요한 이유?

- 해당 테이블에 없는 정보 (id가 있는데 누가 이 id인지 알고싶다. 그런데 이 테이블에는 이름이 없다). 분리해서 저장하고 필요할 때만 합친다.
- 그렇다면 한 테이블에 다 넣으면 안되나? 굳이 나눠서 저장하는 이유가 뭔가?
    1. 데이터 중복 - 한 고객이 주문을 100번 했다면 그 고객의 이름, 이메일, 주소 등 100번이나 불필요하게 저장됨
    2. 갱신 이상(update anomaly) - 한 고객이 이메일 주소를 변경했다면 그 고객이 주문한 100개의 데이터를 모두 찾아서 이메일 변경해야함. 실수로 하나라도 누락된다면 일관성이 깨져 어떤 정보가 진짜인지 모르게 됨
    3. 삽입 이상(insertion anomaly) - 새 상품이 추가됐을 때 주문자가 없으면 테이블에 넣을 수 없다.
    4. 삭제 이상(deletion) - 딱 1번만 주문한 사람이 있다고 치면, 이를 삭제하게 되면 이메일, 주소 등 고객 정보까지 잃게 됨
    5.  정규화라는 과정을 거쳐 설계함
- 정리하자면 데이터를 저장할 때 중복저장, 삽입, 삭제 갱신 이상의 이슈로 분리해서 저장하고 이를 필요할 때 합치기 위해 join을 사용한다.

### 내부 조인

두 테이블을 연결할 때 양 테이블에 모두 공통으로 존재하는 데이터만을 결과로 보여줌

```sql
SELECT 칼럼1, 칼럼 2
FROM 테이블A
INNER JOIN 테이블B ON 테이블A.연결컬럼 = 테이블B.연결컬럼
WHERE 조건;
```

순서: join으로 합침 → where 필터링 → select 칼럼 추출 

- 실무에서는 어디 테이블의 필드인지 명시하는 것이 가독성을 높이고 컬럼의 소속을 파악하기 쉽기 권장
- 쿼리 최적화기: 데이터베이스 내부에서는 쿼리를 더 효율적인 방식으로 실행. 결과는 같음

**조인과 집합**

- 내부 조인은 두 테이블의 교집합을 찾는 것과 같다

→ 어느 한쪽에만 데이터가 존제하는 경우에는 결과에 포함시키지 않고 양쪽 모두에 연결고리가 있는 데이터만을 짝지어 보여줌

**내부조인과 조인방향**

- 내부조인은 양방향. A→B로 조인할 수 있다면 B→A로 조인 가능하고 결과는 같다

**그럼 조인 순서는 언제 중요할까?**

- 쿼리를 읽는 사람의 입장에서 어떤 데이터가 중심이 되는지에 따라 순서를 정하면 가독성 향상

**테이블 별칭(Alias) → 가독성을 높임**

- 테이블이름 (AS) 별칭. AS 보통 생략
- 컬럼 별칭은 AS 사용.
    - 어떤 것이 컬럼이름이고 어떤 것이 별칭인지 즉시 파악하기 힘들기 때문
        - ex) SELECT salery * 12 annual_salary → SELECT salery * 12 AS annual_salary

### 외부 조인

한쪽에는 데이터가 있지만 다른 한쪽에 없는 데이터까지 포함해서 보고 싶을 때 사용

- **LEFT OUTER JOIN**: 교집합 영역 + 왼쪽 테이블 데이터
    - LEFT JOIN 구문의 왼쪽(FROM 절) 에 있는 테이블이 기준
    - 오른쪽 테이블에 짝이 맞는 데이터가 없으면 NULL값으로 채워짐
- **RIGHT OUTER** **JOIN**: 집합 영역 + 오른쪽 테이블 데이터
    - RIGHT JOIN 구문의 오른쪽 (JOIN 절) 에 있는 테이블이 기준
    - 왼쪽 테이블에 짝이 맞는 데이터가 없으면 NULL값으로 채워짐
- **FULL** **OUTER JOIN** (MySQL X): 왼쪽 + 오른쪽

테이블 순서를 적절하게 바꾸면 LEFT, RIGHT를 적절하게 바꿔써도 결과는 같다

---

### **조인의 특징**

- 조인하면 행 개수가 늘어날 수 있음
    - Primary Key: 테이블에서 각 행을 고유하게 식별하는 값. (중복 없음)
    - Foreign Key: 타른 테이블의 PK를 참조하는 값
    - FK → PK 참조 : 행 개수 늘어나지 않음
    - PK → FK 참조 : 행 개수 늘어날 수 있음
        - PK쪽에 데이터를 복제해서 FK쪽과 관계를 맺음

→ 중요한 이유: **데이터가 어떻게 변하는지 이해해야 SUM, AVG, COUNT 같은 집계함수를 올바르게 사용하고 원하는 분석 결과를 정확하게 도출할 수 있음.**

- 조인의 유연성
    - 보통 PK - FK 관계로 조인을 하는것이 일반적이지만, 데이터타입만 같으면 어떤 열로 조 가능

### 셀프 조인

자기 자신 테이블과 조인 → 한 테이블에서 자신의 컬럼이 같은 테이블의 다른 컬럼을 참조하는 구조

- SELF JOIN 은 다른 조인처럼 JOIN 명령어를 쓰지않고 하나의 테이블에 다른 별칭을 부여해 두개의 테이블을 사용하는 것처럼 인식
- 계층형 데이터를 다룰 때 주로 사용

---

### 크로스 조인

기존 INNER, OUTER, SELF 조인은 테이블에 존재하는 관계를 찾아내는 작업이었음.

크로스 조인은 짝이 없거나 관계가 없는 두 잡든을 가지고 조합을 만들 때 사용

- 한 쪽 테이블의 모든 행을 다른 쪽 테이블의 모든 행과 하나씩 연결
- INSERT INTO 테이블 (행1, 행2, 행3, …) : 쿼리 결과를 테이블에 삽입
    - 대량의 초기 데이터를 효율적으로 구축하거나, 기존 데이터를 가공하여 새로운 테이블에 저장하는 등의 작업
